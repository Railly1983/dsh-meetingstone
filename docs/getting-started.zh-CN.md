# 五分钟开始使用集合石

集合石让你在 DSH 中配置「角色 → CLI → 模型 → 职责」，用自然语言派发跨 CLI 任务。
**安装插件不等于自动安装或登录所有外部 CLI。**

## 1. 安装

**优先推荐**：在 DeepSeek Harness 的插件管理 / 市场搜索 `dsh-meetingstone` 并安装，
核对来源为 [Railly1983/dsh-meetingstone](https://github.com/Railly1983/dsh-meetingstone)。

用 DSH CLI 管理 `desktop` Profile 时，公开 npm 包可直接安装：

```powershell
dsh plugin --profile desktop add dsh-meetingstone
```

`desktop` 是 Profile 名示例，请换成你实际使用的 Profile。兼容要求见 `package.json`
的 `engines.dsh`：当前为 `>=0.2.2-rc.1 <0.3.0-0`。不同 DSH 版本可能要求重启后设置入口才出现。

## 2. 连接可用的 CLI

打开 **DSH 设置 → 集合石**，先看外部 CLI 连接状态。安装、登录、Provider 和模型可用性是不同的事情：

- CLI 没安装：按该 CLI 的官方指引安装。
- CLI 已安装但 DSH 不支持派单：检查相应的官方子代理 Provider 是否已安装和配置。
- CLI 已登录但没有额度：到对应服务商检查；集合石无法凭安装状态推断余额。
- 模型列表显示「未知」：通常意味着相应 CLI / Provider 不提供可枚举的能力，需要查看本机配置。

Provider 安装细节见 [安装与连接 CLI](installation.md)。**不要把任何示例里的固定 Windows 路径直接复制为自己的路径。**

## 3. 配置一个角色

插件自带 3 个默认角色（执行者 / 审查员 / 调研员），装完即可派单，**不需要先配 CLI**。
它们只在你还未配置任何角色时出现，不会覆盖你已有的配置。也可以按需新增或改成外部 CLI：

| 配置项 | 示例 |
| --- | --- |
| 名称 | 执行者 |
| 角色设定 | 负责常规代码与测试；只修改授权范围；完成后报告改动与测试证据 |
| CLI | 选择你已经可用的 CLI |
| 模型 | 从已发现 / 已配置的候选模型中选择 |
| 思考强度 | 以该模型真实支持的选项为准 |

你可以继续加「审查员」等角色，最好映射到不同 CLI / 模型以便独立复核。

## 4. 第一次派单

在 DSH 对话中试试：

> 让执行者检查当前仓库的 README 和启动脚本是否一致，只读分析，不修改代码。请给出具体文件、问题和证据。

DSH 可选择集合石角色派单工具执行。运行结束后，用集合石工具查询任务状态、执行记录和产物；
需要复核时，再单独要求审查员检查上一个结果。

**注意**：这是一个自然语言协作示例，**不是强制的只读权限保证**。
项目当前不提供由集合石强制实施的安全沙箱；需要强权限隔离时，请配置底层 CLI / Provider 的正式权限机制
（见 [安全与权限](security.md)）。

## 5. 什么时候用并行？

小任务先串行。只有任务相互独立、确实需要提速、文件改动互不重叠时才开启多实例，并检查各任务的独立 Git worktree。
Worktree 不会自动帮你合并结果，也不能防止获得系统权限的工具修改其他目录。

> **多子代理模式会大幅度增加 token 消耗，建议仅在重要长任务情境下启用。**
> 每个子代理都要重新读一遍上下文，任务拆得越碎、消耗放大越明显。
