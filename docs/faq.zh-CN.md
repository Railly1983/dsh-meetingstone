# 常见问题

### 和 DSH 原生 Subagent、Agent Teams 有什么区别？

DSH 原生功能负责子代理执行、生命周期、权限和团队协作。集合石增加角色到不同 CLI / 模型的映射、本机 CLI 检测、结构化派单、执行记录以及可选工作树隔离。两者是互补关系，不必二选一。集合石不自建工作台、不重造任务队列。

### 安装集合石以后，我原来的 CLI 订阅和积分会自动共享吗？

不会。集合石通过 DSH 已配置的 Provider 调用相应 CLI，实际使用哪个账号、模型和计费渠道由底层 CLI / Provider 决定。请遵守各服务商的使用规则。安装成功不等于认证或额度可用。

### 插件会预置角色吗？会改我已有的角色吗？

**会预置，但只在你自己还没有任何角色时。** 装完自带 3 个默认角色（执行者 / 审查员 / 调研员），全部走 DSH 原生子 Agent，不绑定外部 CLI 或模型，因此开箱即可派单。

一旦你配置过自己的角色（哪怕只有一个），默认角色就**完全不介入**：不合并、不覆盖、不追加，也不会被写进你的配置文件（只在内存生效，你不点保存就不会固化）。

### 为什么角色开关显示「已启用」，但任务仍可能失败？

「已启用」代表用户选择；「可执行」还依赖 CLI、Provider、模型和运行环境。服务端额度无法可靠获取时应显示未知，不把「已安装」伪装为「有余额」。绿色只代表路由可用。

### 同一角色可以同时执行多个任务吗？

具备相应执行与并发条件时可以。多实例应各自拥有任务和隔离工作区，但不代表总 Token 更少。小任务默认串行，长且独立的任务再考虑并行；用 `limits.maxParallelWritesTotal` / `maxParallelWritesPerSession` 控制上限。

### 能否让 Codex 或 CodeBuddy 任务中途直接续聊？

不要把不同通道的行为混为一谈。某些进程内通道支持真实插话；部分外部 CLI 的「调整任务」采用终止原任务并根据已有产出重新启动，可能失去原生会话连续性。使用前请确认回执里的 `steerMode` / `steerNote`。

### Worktree 能阻止 Agent 访问我的其他文件吗？

不能。它是 Git 文件布局隔离，不是权限沙箱。各工作树仍属于同一系统账号，权限限制需要由 CLI、Provider 和操作系统实施。改动也不会自动合并；插件刻意不自动删除工作树，以保护未合并改动。详见 [工作树隔离](worktree-isolation.md)。

### 是否会降低 Token 成本？

集合石帮助你按角色选择不同执行工具，也提供精简的结果接口。但多 Agent 协作不天然省 Token；重复上下文、独立冷启动和交叉审核都可能增加消耗。应以实际完成任务的总用量判断收益。

### 是否需要写代码才能使用？

普通使用的目标是通过 DSH 设置页配置角色。但部分 Provider 的安装、登录和参数配置仍可能需要命令行或编辑 DSH profile。查看 [5 分钟快速开始](getting-started.zh-CN.md) 与 [安装与连接 CLI](installation.md)；配置不成功时先看 CLI / Provider 的诊断信息。
