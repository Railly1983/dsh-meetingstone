## 4. 三色开关

> **最终色语义（Lead 裁决 2026-11-12，D1 以此为准）**：**灰 / 黄 / 绿** 三色，**不引入第四色**。
> - 灰 = 关闭（userPreference=disabled）或依赖阻断（readiness≠ready）
> - 黄 = 启用且额度可靠确认耗尽（quota=exhausted）
> - 绿 = 启用且正常 / 额度未知（available / unknown / not_applicable）
> 依据：交接文档「灰色关闭/阻断」；宿主没有危险色语义 token，多一色会被误读成错误/危险。task-11 原描述的颜色表述以本裁决为准，D1 正式记录同样只用灰/黄/绿。

### 4.1 三色与配置/状态一致

- **预期**：每个角色行的颜色由 Host `deriveRoleView` 派生：**灰**=关闭或依赖阻断，**黄**=启用且额度耗尽，**绿**=启用且正常/额度未知；三色之外不引入第四色。Switch 仍是开/关两态，颜色只表达状态。
- **验证步骤**：构造灰/绿必测样例（关闭、依赖阻断、可用），黄在额度可构造时加测 → 逐行截图 + 对照 config 与宿主状态（`deriveRoleView` 输入）。
- **证据形式**：三色状态截图 + 状态来源说明（config / preflight / quota）。
- **失败判定**：颜色与配置不一致、或颜色被当成第三态控件（点击循环三态）。

## 10. 真机操作准备清单（执行前逐项确认）
