## 第二步：5 项目视确认（约 5 分钟）

打开 DSH → 设置 → 集合石。

### ① 两个区的排布（U1）

**看什么**：页面从上到下应该是

```
外部 CLI 连接      ← 区 1
  [Codex        ] 开
  [CodeBuddy    ] 开
  [Claude Code  ] 开

全局角色库          ← 区 2
  唐僧 · 悟空 · 八戒 · 沙僧 · 小白
  [管理角色]
```

**通过标准**：两个区上下排布，间距看起来舒服，不拥挤也不松散。
**失败**：只有一区、或两区挤在一起看不清。

---

### ② 点「管理角色」在页内展开（U2）

**看什么**：点一下。应该

- 面板**在原位置展开**（页面往下长）
- **不跳转**到别的页面
- **不打开**右侧栏
- 按钮文字变成「收起」

**通过标准**：页面没有跳走、右侧栏没动。
**失败**：跳到别的页、或右侧栏弹出东西。

### ③ 角色列表长什么样（U8）

**看什么**：展开后应该看到 5 个角色，每行是

```
唐僧         [开关]
悟空         [开关]
八戒         [开关]
沙僧         [开关]
小白         [开关]
```

顶部还有一句说明：
> 颜色仅表示启用与依赖就绪状态，不表示实时额度。

**通过标准**：
- 角色名是**中文**（不是 `role-tangtang` 这种）
- 每行左边是名字，右边是开关
- **颜色只有绿色和灰色**，没有黄色、没有红色
- 顶上那句说明在

**失败**：
- 名字显示成 `role-xxx` → 报告我
- 出现黄色或红色 → 报告我（这是回归）

## 附：为什么只剩这 5 项

原本 D1 有 46 步。经过两轮自动化：

| 阶段 | 人工步数 | 说明 |
|---|---|---|
| 最初 | 46 步 | 全部要人眼 |
| 加静态核对后 | 22 步 | 24 项自动化 |
| 加交互核对后 | **5 项** | 又自动化 20 项 |

剩下这 5 项之所以不能自动化，是因为它们依赖**真实像素**和**真实交互链路**：

- 排布是否美观 → 需要眼睛判断「好看」
- 点击是否跳转 → 需要真实浏览器事件
- 颜色是否正确 → 需要真实 CSS 计算后的像素
- 下拉是否有内容 → 需要真实 React 渲染 + 事件绑定
- 刷新是否报错 → 需要真实宿主 Gateway 往返

这四项脚本都做不到，只能你看。
