## 4. Jobs 取消与槽位释放

**步骤**：
1. 派发一个预期 ≥30s 的外部任务（codebuddy/ACP 只读长任务，`isolation:"none"` 便于观察），记 `childId`/`jobId`。
2. 运行中调用 `meetingstone_cancel_task({childId})`。
3. 轮询 `meetingstone_get_task({childId})` 至终态（≤60s）。

| 检查点 | 预期 | 证据形式 | 失败判定 |
| --- | --- | --- | --- |
| cancel 回执 | `stopConfirmed:true`；状态 cancelled/interrupted（诚实终态） | cancel 返回值 | `stopConfirmed:false` 或状态伪装 completed → **P0 FAIL** |

| 槽位释放 | 随后再派一个任务能正常启动（不被旧槽位阻塞） | 第二次派单 `ok:true` + childId | 报并发满且长时间不释放 → **P0 FAIL** |
| 进程清理 | 无法直接验进程树时，记录 `unknown`，并注明依据（宿主无公开进程树 API） | run JSON `stopConfirmed` + 说明 | 不伪造“已清理” |

## 5. Worktree 隔离与 overlap

**场景 A（隔离有效性）**：并行派发 2 个任务，`isolation:"worktree"`，写域不重叠（或均只读）。
**场景 B（重叠检测）**：并行派发 2 个任务，两者都报告/改动同一文件（只读任务可让两者输出同一文件路径作为 evidence；写任务需真实改同一文件）。

| 检查点 | 预期 | 证据形式 | 失败判定 |
| --- | --- | --- | --- |
| worktree 独立 | 两个 childId 的 `worktree.path` 不同、`baseSha` 相同、分支不同 | 两份 run JSON `worktree` | 路径相同/未隔离 → **P0 FAIL** |
| 主工作区无污染 | 执行前后 `git status --porcelain` 无新增被跟踪文件改动（`isolation=worktree` 下） | 前后 `git status` 对比 | 主工作区被改动 → **P0 FAIL** |
| changedFiles | A 场景两任务 changedFiles 不交叉；只读任务 `changedFiles=[]` | run JSON `changedFiles`/`reportedChangedFiles` | 交叉且无 overlap 提示 → P0/P1 |
| overlapWarnings | B 场景双方 run JSON 都含对方 childId（双向自证） | `overlapWarnings` 字段（含 files 列表） | 缺交集记录 → **P1 FAIL（非阻塞）** |
| 只读口径 | 只读任务 `changedFiles=[]`，不得产生 overlap 假阳性 | run JSON | 只读任务出现写文件 → P0 |
| 产物位置 | 外部 CLI 产物落在 worktree 内 `.meetingstone/runs/` 时，记录路径并注明主工作区不可见（C1 F3 已知边界），不判失败 | artifacts 路径 + 说明 | — |

| 场景 | 实际 | 结论 |
| --- | --- | --- |
| A 隔离 | `238f53b6…` 与 `583c7a4a…`：worktree 路径不同（`d4008e88…` / `7d4d46e1…`）、baseSha 相同 `4d0219c0`、分支各自独立；主工作区 `git status` 无任务产生的被跟踪文件改动 | **PASS** |

## 7. 缺陷分级与处置

| 级别 | 定义 | 处置 |
| --- | --- | --- |
| **P0（阻塞发布）** | `npm run verify` 失败；codebuddy/in-process 核心派单失败；取消后槽位泄漏/Job 不终态；worktree 未隔离或污染主工作区；run 记录缺关键字段（provider/model/status/childId）；B2 组合被静默降级 | 阻止 0.1.0-alpha.4；Lead 决定修复或回滚 |
| **P1（不阻塞，记录）** | codex/claude 额度/凭证 BLOCKED；三面板展示差异；overlapWarnings 边界；UI 文案；J1 报告口径缺失 | 写入已知问题与发布说明，可发布 |
| **P2（观察）** | 耗时统计、artifact 回收、trace 信息 | 记录，不阻塞 |

BLOCKED 与 FAIL 的区别：前置条件（P1–P6）未满足 → BLOCKED；前置已满足但行为不符 → FAIL。
