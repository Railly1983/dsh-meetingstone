## U1 设置页只剩两个区

- **点哪里**：打开 DSH 设置（左下角齿轮/侧栏「设置」）→ 左侧列表找插件「集合石」→ 右侧看内容。
- **预期看到**：只有两个区：①「外部 CLI 连接」（Codex / CodeBuddy / Claude / DeepSeek Harness 等行，每行一个开关）；②「默认角色配置」（取经角色、一句说明、角色数量、「管理角色」按钮）。没有「高级设置 / 并行 / 调度 / 通道实例 / 配置文件路径」等。
- **算通过**：只有这两区、顺序一致、没有多余区块。
- **算失败**：出现第三区或任一被删项仍在（折叠起来也算）。
- **截图**：整页设置（含两个区标题）。

## U2 「管理角色」在设置页内展开、不跳走

- **点哪里**：设置页 → ②默认角色配置 → 点「管理角色」。
- **预期看到**：**当前设置页内**展开「全局角色管理」区域，列出角色名和每行的启用开关；页面不切换、不跳到会话页、**不打开右侧栏**。区域内有「返回/收起」可回设置主区。
- **算通过**：管理角色就在设置页里出现，地址栏/页面没变。
- **算失败**：页面跳转、右侧栏被打开、或打开的是会话角色面板。
- **截图**：点「管理角色」后整页（要同时看到设置页标题和管理角色列表）。

## U6 角色编辑器：4 CLI + 模型有值 + 强度有值 + 刷新能力

- **点哪里**：任一角色编辑页，从上往下看字段。
- **预期看到**：字段依次为：名称、简称、**角色设定**（一个大文本框，不再同时有「描述」和「Prompt」）、CLI、模型、思考强度；头部有「刷新能力」。
- **必须检查**：
  1. CLI 下拉**只有 4 个**：DeepSeek Harness / Claude Code / Codex / CodeBuddy，**没有 ch-* 字样**；
  2. 打开即有模型值（如 CodeBuddy 下应能看到 glm-5.3-flash / hy3 / hy4free / kimi-k3.1-pro 等，来源标注「配置」；Codex 下 gpt-6-astra / gpt-6.1-sol）；选一个模型后**思考强度有值**（CodeBuddy 本机应显示 high「配置」）；
  3. 点「刷新能力」不报错，来源标注变化合理（动态/配置/静态/未知）；
  4. 选 DeepSeek Harness 时模型为空并置灰标「不支持」——这是预期，不算失败；
  5. 切换 CLI 后模型列表跟着变、切模型后强度跟着变。
- **算通过**：4 个 CLI、模型有值、强度有值、能刷新、来源标注可读、不支持时置灰。
- **算失败**：显示 ch-*、模型/强度为空且无「不支持」说明、刷新报错、同时存在「描述」「Prompt」、出现「通道」。
- **截图**：编辑器字段全貌 + CodeBuddy 模型下拉 + Codex 模型下拉 + 强度下拉（各 1 张）。
- **补充**：若模型/强度仍为空，请把编辑器截图 + 浏览器控制台 Network 里 `meetingstone/list` 返回的 `global.capabilities` 片段发给 Lead（这是本轮重点排查面）。

## U8 两色开关（灰 / 绿，没有黄色也没有红色）

> **2026-11-12 口径变更（唐僧裁决）**：V1 从三色收敛为**两色**。
> 黄色及「确认无额度」的产品承诺正式撤回 —— 宿主没有额度查询 API，
> 用失败记录推断会让「历史某次失败」伪装成「当前无额度」。
> 详见 `docs/plan/2026-11-12-yellow-state-verdict.md`。

- **点哪里**：设置页 → 管理角色 → 看每行左侧开关颜色。
- **预期看到**：开关只有**开/关两态**，颜色只表达两件事：
  - **灰** = 已关闭，或依赖阻断 / 就绪状态未知
  - **绿** = 已启用且依赖就绪。**不声明额度充足，也不表示实时额度**
- **算通过**：颜色只有灰/绿；**不应出现黄色**（出现即回归）；不应出现红色；
  开关只有开/关两态；关闭的角色显示灰色。
- **算失败**：出现黄色或红色、或开关能点出第三种状态。
- **截图**：全局角色列表（至少 3 行）。
- **操作**：把任一角色开关关掉再打开，确认**即时生效**（不刷新页面），重开后状态保持。
- **顺带确认**：角色区顶部应有一句
  「颜色仅表示启用与依赖就绪状态，不表示实时额度。」
