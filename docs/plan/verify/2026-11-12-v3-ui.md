# V3 验证：Team UI 与 Subagent UI 分工对照（2026-11-12）

> 执行：小白（Team 成员）｜阶段 A 验证，不改产品代码 / profile / 不重启 DSH
> 结论一句话：**Team UI、Subagents、Background Tasks（Jobs）、MeetingStone Runs 是四层不同数据，字段级零重复；重叠只发生在“名称”上。MeetingStone 自建 UI 应只保留 Runs 执行记录，不再新建任务板 / 成员列表 / 子代理目录 / Job 列表。**

## 1. 结论（先给判断）

| 面板 | 定位（一句话） | 数据源 | 可操作性 |
| --- | --- | --- | --- |
| **Team UI**（Agent Teams） | 协作编排：谁在做什么任务 | Team 持久记录（`team.members` / `team.tasks`） | 只读面板：点成员打开其会话；任务字段**只能**通过对话里的 `team_task_*` 工具改 |
| **Subagents**（子智能体目录） | 本父会话派生了哪些子 Agent 会话 | 宿主 `subagent/catalog` + `subagent/descriptor` | 折叠/展开、在侧边栏打开子会话 |
| **Background Tasks**（Jobs） | 真实后台任务进程 | 宿主 `ctx.jobs` | 停止（两击确认）、看实时输出 |
| **MeetingStone Runs** | 每次派单的执行档案 | `.meetingstone/runs/<childId>.json` | 查询、取全文、取消派单（工具层） |

**关键判定**：四者不是同一份数据的不同皮肤，也不存在真正的“信息重复”；唯一重合是**名称**（任务 subject / 派单 label / 角色名），且由同一套命名规则约束。V2 的两单真实派单验证了这一点（见 §3）。

## 2. 证据级别与方法（如实说明）

- **工具层实测**：`list_agents`（Team 成员）、`team_task_list/get`（共享任务板）、`job_list`（Jobs）、`meetingstone_list_runs/get_task`（Runs）在本会话真实调用返回；用 2 单真实派单产生数据。
- **宿主源码级**（只读提取本机 `app.asar`，未改宿主）：
  - Team：`dsh/node_modules/@deepseek-ai/dsh-experimental-client-ui-agent-team/lib/client.js`（32,553 B）
  - Subagents：`dsh/node_modules/@deepseek-ai/dsh-client-ui-subagent/lib/client.js`（65,163 B）
  - Jobs：`dsh/node_modules/@deepseek-ai/dsh-client-ui-jobs/lib/client.js`（45,541 B）

数据：`12:58 沙僧 ACP（childId c23cf548…）`、`12:58 八戒 in-process（childId 7aa5d56f…）`（详见 V2 文档）。

| 数据 | Team UI | Subagents | Background Tasks | MeetingStone Runs |

| 沙僧 ACP 派单 | **无**（`list_agents` 全程 4 名成员不变） | **无**（本机无 `c23cf548…` 会话目录；外部 provider `delivery:'caller'` 不写 external catalog） | **有**（completed，label=`沙僧 · V2闭环验证-沙僧只读核对…`） | **有**（9254 B 记录） |
| 八戒 in-process 派单 | **无** | **有**（本地子会话 `sessions\--D-MeetingStone--\7aa5d56f-…` 存在；行标题取 `label`=`八戒 · V2闭环对照-八戒in-p…`） | **有**（completed） | **有**（7774 B 记录） |

结论：**同一份运行数据不会同时出现在两个面板**；派单执行过程只落在 Jobs + Runs，会话谱系只落在 Subagents，任务编排只落在 Team。MeetingStone 现在“一个派单记录在 Runs”与“Job 在 Jobs”是互补，不是重复。

## 4. 字段级对照（面板源码 + 实测数据）

### 4.1 Team UI（`dsh-experimental-client-ui-agent-team`）

位置：会话页头 `conversation.session.header.actions`，id=`agent-team`，order=`-20`，触发文案 `智能体团队`；展开为下拉面板（500px，窄屏 320px）。
- **成员区**标题「成员」+ 计数；每行：**名称**、**模型**（`modelSelection.next.model`）、**状态**四态（运行中 / 未运行 / 准备中 / 失败）、`error` 文本（有则显示）、当前会话高亮「当前会话」、点击「打开成员会话」。
- **共享任务区**标题「共享任务」+ 计数；空态「暂无共享任务，可以通过对话创建」；每张卡：**subject**、**状态**（待处理 / 进行中 / 已完成 + 状态点）、**描述**（两行截断，可展开/收起）、**任务 id**、**Owner / 未分配**、「可开始 / 被依赖阻塞」、**依赖** `blockedBy` 列表、**写入范围** `writeScopes` 列表与 `writeScopeWarnings`。
- **只读**：源码中无 claim/complete/reassign 按钮，只有“打开成员会话 / 展开描述”两类点击 → 任务状态只能由对话工具改。

### 4.2 Subagents（`dsh-client-ui-subagent`）

位置：会话页头（父会话视角），行标题 = `entry.label ?? entry.id`（`label` 创建时冻结），可折叠子树。
- 每行：**行标题**、**active/inactive** 状态点、**token 总量**（`uncachedInput + output + cacheRead + cacheWrite`，如 `12.3K tok`）、**活跃耗时**（紧凑显示，tooltip「总活跃耗时：…」）、当前会话高亮、「在侧边栏打开 {label}」、展开/收起下级。
- 加载态「正在加载子智能体…」；**没有**任务/负责人/依赖/写作用域字段。
- 边界：**无独立全局页**，是父会话页头的目录投影；父会话归档后整个目录不可达（既有审计结论）。

### 4.3 Background Tasks（`dsh-client-ui-jobs`）

- 触发器计数「N 个后台任务运行中 / N 个后台任务」；按「进行中 / 已结束」分区。
- 每行：**label**、**状态**（运行中 / 正在停止 / 已完成 / 已取消 / 已失败）、**一行 progress 或 detail**、**耗时**（已运行 / 耗时）、展开**实时输出**、运行中行有**停止**（再次点击确认）。
- 实测：两单都以 `kind=meetingstone-dispatch` 出现，并在完成后留在列表（completed）。

### 4.4 MeetingStone Runs（自有）

字段（run 记录实测）：`childId`、`role`、`channel`、`provider`、`model`、`status`、`stopReason`、`failureClass`、`hint`、`title/taskSpec`、`contextPack`、`result/summary/handoff/evidence/openIssues`、`changedFiles`、`isolation/worktree`、`overlapWarnings`、`routing`、`recordPath`、`createdAt/finishedAt`。
工具：`meetingstone_list_runs`、`get_task`、`get_run_artifact`、`cancel_task`。**这是唯一记录“角色 → 通道 → provider/模型 → childId → 结构化交接”的地方。**

## 5. 最终分工表（可直接作为 UI 开发依据）

| 维度 | Team UI 显示 | Subagents 显示 | Background Tasks 显示 | MeetingStone Runs 显示 |
| --- | --- | --- | --- | --- |
| 名称 | 成员名 / 任务 subject | 子会话 label | Job label | 派单 title + 角色名 |
| 状态 | 成员四态 + 任务三态（含依赖/可开始） | active/inactive | 运行/停止中/完成/取消/失败 | 执行七态 + resultStatus |
| 负责人 | **ownerName（人）** | 只有父子关系（无 owner） | 无 | roleId（**派单目标，不是成员**） |
| 耗时 | 不显示 | 活跃耗时 | 已运行/总耗时 | createdAt→finishedAt |
| 依赖 | **blockedBy / ready** | 不显示 | 不显示 | 不显示 |
| 模型 | 成员模型 | 不显示 | 不显示 | provider/model（ACP 可能为空） |
| 结果/证据 | 不显示 | 结果在子会话内，行上不显示 | 实时输出（进程级） | **完整结果/证据/工作树/交接** |
| 操作 | 打开成员会话（只读） | 打开/折叠/侧栏打开 | 停止 + 实时输出 | 查询/取全文/取消 |
| 绝不显示 | 派单 childId、Token、工作树、Runs 字段 | 任务/负责人/依赖 | 任务目标/验收/证据 | 任务依赖/成员状态/Job 实时输出 |

**一句话分工**：Team 看“**任务编排**”，Subagents 看“**会话谱系**”，Jobs 看“**进程执行**”，MeetingStone Runs 看“**派单档案**”。

**MeetingStone 职责边界（V3 硬约束）**：

1. **只保留 Runs 执行记录**（+ 既有角色/通道配置页、会话覆盖右侧栏、页头派单入口）。
2. **绝不新建**：任务板（用 `team_task_*`）、成员列表（用 `list_agents`）、子代理目录（用 Subagents 面板）、Job 列表（用 `ctx.jobs` + Jobs 面板）。
3. 若未来需要“任务 ↔ 派单”关联：**只在 Runs 记录里加 `taskId` 外键**（可选字段），不往 Team 任务里塞 run 细节，避免双写与状态漂移。
4. 角色 ≠ Team 成员：角色是派单目标（CLI/模型），成员是可持续交互的 agent；Runs 里绝不写 `ownerName`，Team 里绝不写 childId。

## 6. 重叠与风险（需要后续注意）

| 项 | 现状 | 建议 |
| --- | --- | --- |
| 两个入口同处会话页头 | 「智能体团队」下拉（order -20）与 Subagent 目录/谱系是相邻两个触发器 | 文案已区分（团队 vs 子智能体），但需真机确认视觉不混；MeetingStone 不要再往页头加第三个“任务/派单”触发 |
| 名称重合 | 任务 subject（人写） vs 派单 label（`buildTaskLabel` 生成） vs 子会话 label（同一个 `buildTaskLabel`） | 保持“一处实现”命名规则；Team subject 不要自动复制到 run title |
| 状态语义 | 四套独立状态机 | 禁止互相翻译/合并；UI 分别标注来源 |
| Team UI 只读 | 任务卡无操作按钮 | 确认是宿主设计（experimental）；MeetingStone 若要“一键完成”需走工具层，不自建按钮 |
| Team UI 实验性 | 包名 `dsh-experimental-*` | 字段可能随宿主流漂移；MeetingStone 不依赖其内部结构，只依赖 `team_task_*` / `list_agents` 工具 |
| 外部 CLI 不进 Subagents | `delivery:'caller'` 下宿主不写 external catalog（官方 opt-in 路径为 `delivery:'parent'`） | 产品文案不承诺“外部任务出现在 Subagents”；统一指向 Jobs + Runs |
