## 4. 三条问题最终判定（Goal R2 复核）

① **设置页「管理角色」错跳会话面板**：成立（`src/client/index.js:1504-1509` → `openRoles` → `openRolePanelOf` → `sidebarRight.openTab`；tab 注册 scope=session；settings.section root 无 sessionId）。修正：通道数据其实已具备（`fullSnapshot`），真正缺的是 `roleView` 的 description/prompt/source 与设置页内联全局视图；写路径 `updateGlobalRole`/`sanitizeRolePatch` 已就绪。

② **角色编辑器概念混乱**：成立。`adapter` 注释「spec 不收 model/reasoning」仅对外部 provider 成立；`spec.request.agentOptions` 对声明该能力的后端生效（spawn: `agentOptions:true/agentPreset:true`；ACP/Codex/Claude 全 false）。in-process 可真正传模型与 reasoningEffort；外部通道必须留在 provider 行。UI 缺的是**如实展示来源**，不是多给下拉；描述与 prompt 同时参与人设与路由，合并需联动 adapter/routing/register。

③ **能否复用 DSH 原生角色**：**partial**。`ctx.agentPresets.register` 可编程注册且可按 activation 绑定，但仅 spawn 支持；preset 只是插件组合，无别名→CLI/参数/cwd/模型映射；外部后端拒绝；无 YAML 写回接口。本 profile 已启用 `dsh-experimental-agent-team-profile`（session 级共享 cwd），进一步确认原生不做跨 CLI 路由。结论：角色表/别名/路由保留自研，in-process 可选接 preset 承载 persona（P2）。
