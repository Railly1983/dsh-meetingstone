# 配置集合石：先配置角色，再考虑高级参数

**普通用户优先在 DSH 设置页配置。** 集合石不是独立工作台，团队任务板、权限和子代理生命周期仍由 DSH 原生功能管理。

> 现行实现（0.1.0）：可视化配置是**全局角色**（设置页 → 集合石 → 全局角色库），
> 项目 / 会话级角色覆盖已下线。旧的字段级说明已归档到
> [历史配置参考](reference/legacy-configuration.md)（含项目级 / 会话级覆盖，仅供维护者查证，**不再是现行用法**）。

## 从一个角色开始

在设置页创建或编辑：

| 字段 | 怎么填 | 建议 |
| --- | --- | --- |
| 角色名称 | 你会在对话中使用的名字，例如「执行者」 | 简短、可记忆 |
| 角色设定 | 职责 + 人设 + 工作守则（合并后的单一字段） | 例如「完成常规开发和测试，只改授权范围，完成后报告改动与测试证据」 |
| CLI | 连接到真实安装的 Codex、CodeBuddy 等 | 先确认当前 CLI 可用 |
| 模型 | 该 CLI / Provider 已发现或已配置的模型 | 不假定某个静态模型一直可用 |
| 思考强度 | 模型真正支持的选项 | 简单任务不必默认最高档 |
| 启用 | 用户是否希望系统使用该角色 | 这是用户意愿，不代表额度保证 |

插件**自带 3 个开箱即用的默认角色**：执行者 / 审查员 / 调研员。它们全部走 DSH 原生子 Agent
（`in-process`），**不绑定任何外部 CLI 或模型**，因此装完就能直接派单，也不需要先配 CLI。
默认角色只在**你还没有任何角色**时出现；一旦你自己配置过角色，它们就完全不介入，
**不会覆盖或合并你已有的配置**，也不会被写进你的配置文件（只在内存里生效）。

需要更多角色、或想把某个角色换成外部 CLI / 指定模型时，再自己添加或编辑。

仓库根目录的 `personas.json` 与 `examples/meetingstone.desktop.yml` 是**开发期示例**：
前者绑定了作者本机的 CLI / 模型，后者包含特定机器的权限设置，两者都**不参与运行时**，
也不会被打进发布包（发布门禁显式禁止）。需要团队命名灵感时可以参考，不要整份照搬。

## CLI 连接与角色状态不是同一件事

- **CLI 连接状态**：是否安装、能否找到有效入口、Provider 是否就绪。
- **角色启用状态**：用户想不想让此角色参与派单。
- **额度状态**：服务端是否确实还有可用额度。没有可靠接口时显示未知。

颜色不能替代这三种信息。绿色只代表「路由可用」，**不表示订阅额度充足**。

## 公共上下文与交接规范

角色职责与项目约定保持稳定；每个任务的目标、范围、验收要求放在动态任务内容中。
跨 CLI 时只传递目标、已确认决策、已完成工作、产物、必要证据和待处理问题，
不要默认传递整段聊天历史。Prompt Cache 属于模型服务端机制，插件只能优化请求组织，
不能承诺跨 CLI 命中。

## 高级：直接修改 DSH Profile

插件当前的可视化配置主要是**全局角色**。只有确实需要调整 Provider / Channel、
并发上限、工作树或特殊路由时，才考虑修改 DSH 的 `cordis.patch.yml`。

高级用户应先备份 Profile，按当前版本的字段 schema 编辑并重启验证。
`patch` 是**整值替换**：覆盖 `meetingstone` 行时要把整个 `config` 写全，不是深合并。

常用 `limits`（当前实现默认值）：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `serializeWrites` | `true` | `isolation:none` 时同项目写任务串行（正确性保护） |
| `maxParallelWritesTotal` | `8` | 本插件派发的并行写任务全局上限 |
| `maxParallelWritesPerSession` | `4` | 单一会话的并行写任务上限 |
| `defaultIsolation` | `worktree` | 每任务独立 Git 工作树；`none` 为主工作区串行 |

## 已知技术边界

- 外部 CLI 的模型支持取决于 Provider；部分 CLI 的模型列表未必可动态枚举。
- 插件的 Git Worktree 只隔离默认工作路径，**不是只读权限沙箱**，且不自动删除（保护未合并改动）。
- 某些外部任务「调整指令」实际上是停止后带结果重开，不等同于原生会话续聊。
- DSH Agent Teams 是可选的团队协作能力，不应视为角色模型映射的替代品。
