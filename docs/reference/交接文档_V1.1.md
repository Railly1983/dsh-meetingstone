[Heading 1] 1. 项目定位与不可违反原则
[Heading 2] 1.1 项目目标
[Normal] 开发一个安装在 DeepSeek Harness 内部的轻量原生插件，为 DSH 增加跨 CLI 的角色映射和任务派发能力。目标执行平台为 Claude Code CLI、Codex CLI、DeepSeek Harness CLI、CodeBuddy CLI。用户通过图形化配置角色，再通过自然语言按角色名称或简称派发任务。
[Normal] 产品价值不是重建 Agent 平台，而是让 DSH 已有的团队、项目、任务、Subagent、权限和插件能力能够更方便地组织并调用不同 CLI。
[Heading 2] 1.2 最高原则：复用优先，缺口驱动开发
[List Bullet] 凡是 DSH 当前版本已有的官方功能、插件、Service、API 或 UI，优先直接复用。
[List Bullet] 先检查原生功能，再检查官方插件，再检查配置组合，最后才考虑补充代码。
[List Bullet] 不得为了统一界面或代码风格而重写 DSH 已有功能。
[List Bullet] 任何新增模块、页面、持久化结构或后台服务，都必须说明 DSH 哪个能力无法满足，以及为何不能直接调用或扩展。
[List Bullet] 技术能力必须在用户当前 DSH 版本和目标 Windows 环境中实测，不得只凭包名或文档推断可用。
[Heading 2] 1.3 Clean-room 独立开发要求
[Normal] 本项目必须是全新独立开源项目。用户明确要求不得复用 CLIWorker 的任何代码。CLIWorker 仅可作为需求、历史问题和经验参考。
[List Bullet] 禁止复制 CLIWorker 源代码、函数、模块、代码片段、补丁或测试代码。
[List Bullet] 禁止 Fork CLIWorker 后改名或改造为本项目。
[List Bullet] 禁止将 CLIWorker 作为安装、运行或升级依赖。
[List Bullet] 允许参考其功能需求、历史 Bug、运行问题和已验证的产品交互。
[List Bullet] 本项目必须独立设计数据结构、接口、测试、文档、版本号和发布流程。
[List Bullet] 在仓库中维护 docs/CLEAN_ROOM.md，记录独立开发边界和来源审查流程。

[Heading 1] 2. 第一版范围与明确不做清单
[Heading 2] 2.1 第一版只补齐三类能力
=== TABLE ===

跨 CLI 角色映射 | 角色名称、别名、职责、Provider/CLI、模型、思考强度、权限预设、启用状态 | 只做轻量注册表和配置 UI；Persona/Preset/Skills 优先复用 DSH

[List Bullet] 独立项目管理、团队名册、任务板、任务列表、任务队列。
[List Bullet] 独立 Agent Gateway、独立 MCP Server、独立 Agent SDK。
[List Bullet] 独立 SQLite 数据库或复杂记忆系统。
[List Bullet] 自主多 Agent 自由聊天和复杂自动调度。
[List Bullet] 额度超限后无人监管的自动接替。
[List Bullet] 完整跨平台成本分析和账单核算。
[List Bullet] 修改 DSH 核心代码或维护 DSH 私有分支。
[List Bullet] 复用 CLIWorker 代码或将其纳入依赖。

[Normal] 连接策略的第一优先级是复用 DSH 官方现有 Provider。只有当官方 Provider 无法满足本项目明确要求（例如本机 CLI 检测、特定会话生命周期或可靠用量）时，才增加最薄的补充适配。不得先自研四套 Adapter 再寻找复用机会。
=== TABLE ===
平台 | 优先连接方向 | 必须验证 | 不允许假设

[Heading 1] 5. 最小架构与配置设计
[Heading 2] 5.1 最小架构
[Normal] DeepSeek Harness Host
  ├─ 原生 Plugin Manager / Settings
  ├─ 原生 Workspace / Project
  ├─ 原生 Agent Teams（如当前版本可用）
  ├─ 原生 Subagent / Providers
  ├─ 原生 Jobs / Todo / Session

[Heading 2] 5.3 角色配置字段
=== TABLE ===
字段 | 类型/示例 | 规则

[Heading 1] 6. 角色识别、派单与任务交接
[Heading 2] 6.1 派单流程
[List Number] DSH 主模型理解用户自然语言意图。
[List Number] 调用插件提供的角色派单工具，并传入角色名称/别名和任务要求。
[List Number] 插件在当前项目配置与全局配置中解析固定 Role ID。
[List Number] 检查角色是否启用、Provider 是否可用、模型/思考强度是否受支持。
[List Number] 读取当前 DSH Workspace 项目目录和适用规则。
[List Number] 调用 DSH 原生 Subagent 或 Agent Teams 能力创建任务。
[List Number] 返回 DSH 原生任务/会话引用及执行结果。
[Heading 2] 6.2 最小工具集合

[Heading 1] 7. 安全、权限与项目隔离
[Heading 2] 7.1 权限原则
[List Bullet] 优先复用 DSH 原生 Permission Presets、Approval 和 Sandbox。
[List Bullet] 不能假设父 Agent 沙箱自动限制外部 CLI 子进程；必须实测。
[List Bullet] 外部 CLI 不以管理员权限运行。
[List Bullet] 不复制、不导出、不共享各 CLI 的登录凭据。
[List Bullet] 只传递完成任务所需的环境变量，过滤不必要的密钥和凭据。
[List Bullet] 明确限制工作目录；写入范围必须由操作系统权限或 CLI 原生机制落实。
[List Bullet] 高风险操作使用宿主审批机制；不能只靠 Prompt 约束。
[List Bullet] CodeBuddy 等平台若不支持真正只读模式，不得将其标记为安全只读。
[Heading 2] 7.2 第一版权限档位
=== TABLE ===

[List Bullet] CLI 退出、超时或连接断开时，记录原生任务状态并显示 Unknown/Failed，不伪造成功。
[List Bullet] 重试前检查文件是否已经被部分修改。
[List Bullet] 取消任务后确认子进程及其子进程是否真正退出。

[Heading 1] 8. 用量与额度记录原则
[Normal] 用量统计优先使用 DSH Token Meter 和原生 Usage UI。只在外部 Provider 的 Usage 无法进入原生统计时，才做最小补充。
=== TABLE ===
平台 | 优先数据来源 | 边界
Codex | 官方 App Server/账号限额接口或 DSH Provider 返回 | 窗口与重置时间以接口真实返回为准
Claude Code | CLI/SDK 实际返回的 Token Usage | 成本可能是估算，不等于供应商最终账单
DeepSeek Harness | ACP/SDK 实际返回 Usage | 缺失字段显示未知
