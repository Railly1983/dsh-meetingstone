## 文档说明与决策摘要
本文将“协作效率机制”纳入集合石 V1 核心功能，不作为独立产品、独立工作台或未来附加模块。它应嵌入现有角色配置、任务派发、DSH Subagent、Jobs、Workspace、权限和 Token Meter 链路。
本文中的沙僧审计数字来自用户提供的 35 条运行记录摘要。它们是当前样本的观察值和预计节省量，不代表代码已修改，也不代表所有项目、模型或任务都能获得相同收益。文档没有声称已经独立检查仓库或复现实测。
## 1. 项目目标与设计原则
### 1.1 项目定位升级
集合石不是为了单纯接入 Claude Code、Codex、DeepSeek Harness 和 CodeBuddy，而是为多个 CLI 制定一套标准化协作机制：任务如何描述、上下文如何传递、角色如何选择、执行如何跟踪、结果如何交接、Token 如何控制。
产品定位建议：一个面向多 CLI、多模型的轻量级智能体协作框架，通过标准化任务输入、最小上下文共享、确定性派发、事件驱动执行管理和结构化交接，提高协作效率并降低 Token 消耗。
### 1.2 三条核心原则
不重复探索：已知事实、相关文件路径和已有成果随任务传递，避免 Agent 每次从全仓库重新开始。
不重复表达：不传递完整聊天历史，不让 Agent 复述长文，不把角色人设和无关元数据反复塞进工具回执。
不重复执行：不重复派单、不盲目重试、不做无意义轮询；先检查状态，再决定是否重试。
### 1.3 效率与质量同时优化
Token 下降不能以任务质量下降为代价。所有优化都应同时观察总 Token、主控接收 Token、完成时长、返工/重试、验收通过率。不能只以工具回执变短作为整体节省的证明。

## 3. 第一阶段 P0：必须纳入 V1
### 3.1 工具返回瘦身：摘要默认、全文显式请求
原则：工具默认返回足够做下一步决策的最小信息；只有用户或 Agent 明确需要时才请求全文。
实现注意：摘要不能只做字符串截断。应优先保留任务标题、目标、状态、验收、结果摘要等结构化字段；只有历史自由文本才采用首尾截断。若首尾截断会丢失关键内容，返回摘要加 artifactRef，并允许 full:true。
### 3.2 TaskSpec：标准化任务简报
每个被派发的任务都应有一个最小 TaskSpec。不要把模板做成繁琐表单，也不要为生成简报额外调用一个 AI。主控在理解原任务时直接填充字段，代码只做必填检查。
{
  "taskId": "task-2026-001",
  "title": "审核登录模块权限边界",
  "objective": "检查登录模块是否存在越权访问或权限绕过问题",
  "scope": {
    "include": ["src/auth/", "tests/auth/"],
    "exclude": ["不修改代码，只审查"]
  },
  "acceptance": [
    "列出确认的问题及证据位置",
    "区分真实问题与潜在风险",
    "无问题时明确说明检查范围"
  ],
  "evidence": ["文件路径和行号", "必要的测试结果"],
  "contextRefs": [".meetingstone/context/auth-module.md"],
  "permissionPreset": "read-only"
}
拒绝规则：只有缺少会导致任务无法执行或无法验收的关键字段时才拒绝派单并要求澄清。不得因为简单任务没有复杂 Scope 或 Evidence 字段而机械拒绝。
### 3.3 Context Pack：最小必要上下文
Context Pack 是跨 CLI 协作最重要的效率机制之一。每次派单只传递完成本任务所需的信息，不传递整个项目聊天记录或所有 Agent 的完整输出。
{
  "project": {
    "name": "集合石",
    "workspace": "当前 DSH Workspace 根目录"
  },
  "task": {
    "title": "复核 Codex Provider 任务取消行为",
    "objective": "确认取消后进程树是否退出"
  },
  "knownFacts": [
    "当前 DSH 版本：由环境审计结果注入",
    "已知测试入口：tests/providers/codex-cancel"
  ],
  "files": [
    "src/providers/codex.ts",
    "tests/providers/codex-cancel.test.ts"
  ],
  "priorResults": [
    {
      "summary": "启动和正常完成已通过，取消路径尚未验证",
      "artifactRef": ".meetingstone/runs/task-123/summary.md"
    }
  ],
  "doNotRepeat": [
    "不要重新扫描整个仓库",
    "不要重复测试正常完成路径"
  ],
  "acceptance": [
    "取消后父子进程均退出",
    "提交进程列表或日志证据"
  ]
}
上下文重放上限建议由 64KiB 降至 16KiB，但需先确认该上限作用于哪一类上下文、是否按字节计量、是否影响必要的系统/项目指令。超限时应优先保留结构化任务字段和引用，不得静默截断安全规则或验收条件。
### 3.4 结构化结果与输出预算
禁止子 Agent 以长篇自然语言复述任务背景或过程。要求输出结论、证据、产物引用和未解决问题；完整内容写入项目产物目录。
{
  "status": "completed",
  "summary": "发现 2 个权限检查缺口，均位于授权回调路径；未修改代码。",
  "evidence": [
    {"file": "src/auth/callback.ts", "line": 84, "finding": "缺少租户归属校验"}
  ],
  "artifacts": [".meetingstone/runs/task-123/review.md"],
  "changedFiles": [],
  "tests": ["静态检查完成；未运行集成测试"],
  "openIssues": ["需要确认旧租户兼容逻辑"],
  "nextAction": "交由沙僧修复后再由悟空复核"
}
必须区分两种节省：一是子 Agent 少生成 Token；二是主控少接收 Token。仅把长结果写文件、主控只看摘要，只能确定降低主控上下文消耗，不能自动证明子 Agent 生成量下降。Provider 支持真实 max output 限制时才设置硬上限；不支持时通过任务指令、文件落盘和结果 schema 控制。
### 3.5 进行中重复任务去重
第一版只去重完全相同的进行中任务，不复用已完成任务的旧结果。不能只对 Prompt 做 Hash。
若发现相同进行中任务：返回已有 taskRef 和当前状态，不再创建第二个子任务。若信息不足以证明完全相同，则正常创建新任务。
### 3.6 默认免轮询、事件驱动、批量汇报
主控派单后不持续调用 get_task 轮询；优先等待 DSH 原生任务完成事件/通知。
只有用户询问进度、任务超时、异常或需要决策时才主动查询状态。
多个任务完成后一次性汇报，逐项列出状态、结论、产物和阻塞点。
任务进度更新复用 DSH Jobs，不重复开发状态面板。
如果当前 DSH 版本缺少可靠事件回调，先评估现有 Session/Jobs 通知机制；不要用高频轮询作为默认方案。
## 4. 第二阶段 P1：增强机制
### 4.1 失败快分类、冷却和有限重试
关键规则：重试前必须先检查任务是否已经产生结果或修改文件。超时不等于任务未执行成功。第一版不做无条件自动换模型；先分类、给出建议，后续再由用户批准切换策略。
### 4.2 确定性优先的角色路由
自动角色路由放在 P1。优先使用明确规则，而不是每次调用额外 AI 分类器。
用户明确指定角色时必须尊重用户指定；自动路由只在用户未指定角色或明确启用自动路由时生效。路由结果应可解释，不能悄悄改变 Provider、模型、成本档位或权限。
## 5. 工具契约与最小数据结构建议
下列是建议契约，最终字段必须先对照当前代码和 DSH API，尽量兼容既有 schema，不为追求统一而大规模重构。
### 5.1 建议的摘要截断规则
结构化任务记录优先按字段构建摘要，不直接截断整个 JSON。
自由文本摘要默认保留首 1KB 和末 512B；必须标记 truncated=true 和原始长度。
UTF-8 截断必须按字符边界进行，不能产生非法编码。
全文通过 full:true 或 artifactRef 按需读取。
日志/输出很长时支持按行范围或尾部读取，避免一次返回所有内容。
### 5.2 dispatch 回执最小化
{
  "taskRef": "job-or-subagent-reference",
  "roleId": "role-wukong",
  "roleName": "悟空",
  "isolation": "project-worktree",
  "status": "accepted"
}
不得把完整 role description、系统人设、所有模型参数和完整 Context Pack 原样回传主控。主控已有角色配置时，只返回引用和必要执行元数据。
## 6. 与 DSH 原生能力的关系

## 8. 安全、兼容和风险边界
摘要和截断不能删掉安全策略、权限限制、任务边界或验收标准。
Context Pack 只传当前任务必要的信息；密钥、登录令牌和敏感凭据不得进入任务简报或普通日志。
跨 CLI 交接不能默认共享完整会话或认证状态。
外部 CLI 的权限边界必须由 DSH/操作系统/CLI 实际能力保证，不能只靠自然语言指令。
去重只对确认完全相同的进行中任务生效；不确定时宁可创建新任务。
取消和超时后先确认原进程/任务状态，再允许重试，避免重复写入。
角色路由不得擅自提升权限或切换到更高成本模型。
Provider 不支持的硬输出限制、Usage 字段、取消能力不得伪装成已支持。
## 9. 实施计划与验收标准
### 9.1 第一版明确不做
不做新的独立 AI 调度 Agent。
不做画布、可视化工作流引擎或复杂拖拽编排。
不做独立任务管理面板；复用 DSH Jobs 和 Subagent UI。
不做独立队列、数据库或全量任务历史仓库。
不把所有任务强制变成复杂表单；TaskSpec 按任务类型最小化。
不做默认自动换模型/自动提升权限/自动重试所有错误。
不将完整聊天历史复制给每个 CLI。

## 表格 9

| 失败类型 | 处理原则 | 是否自动重试 |
|---|---|---|
| 429 / Rate limit | 读取 Retry-After 或 Provider 限流信息；冷却后再评估 | 有限重试；不并发轰炸 |
| 认证失败 | 提示重新登录/检查认证，不反复重试 | 否 |
| 权限拒绝 | 报告缺少的权限，等待用户调整 | 否 |
| 超时 | 先查询原任务/进程状态，确认未完成后再决定 | 谨慎，避免重复执行 |
| Refusal / 安全拒答 | 保留拒答原因，检查任务是否触及限制 | 否，不通过换模型绕过安全规则 |
| 进程异常 / 崩溃 | 记录退出码、stderr 摘要、进程状态 | 按错误类型有限重试 |
| 网络临时错误 | 指数退避，设置最大次数 | 可有限重试 |
