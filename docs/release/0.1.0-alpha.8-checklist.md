## 4. 真机验证（关键）

### 4.1 工具是否出现

- [ ] 让 Lead 调一次 `spawn_teammate_as`，或看工具列表里有它

### 4.2 模型是否真的切换（核心）

- [ ] 用 `role: 沙僧` 创建一个 teammate
- [ ] 读该 teammate 会话的 `subagent/descriptor`，确认 `agentProvider`/`agentModel`
      是**角色配置的**（如 `acp-kimi/kimi-k3.1-pro`），不是父会话的
- [ ] 看它的 `request/header`，确认首轮请求就是目标路由（不是先用继承模型跑一轮）

### 4.3 失败路径

- [ ] `role: 唐僧`（绑定外部 CLI）→ 应拒绝并说明「只能跑进程内通道」
- [ ] 不存在的角色 → 应报 `ROLE_NOT_FOUND` 并列出可用角色

## 5. 已知限制（不阻塞）

- 成员名只能拼音（宿主正则硬编码）
- 成员不能改名、不能删除（宿主无接口）
- 现有 `sashi` / `route-probe` / `d1-verifier` / `auditor` 会永久留在面板
